# 05 三维姿态显示

> 对应 README 第 5 项。代码：`armhost/kinematics/dh.py`（正运动学）、`armhost/ui/view3d.py`（渲染）、`armhost/ui/pose_panel.py`（面板）。

## 1. 方案评估与选型

| 方案 | 依赖 / 部署成本 | 适用场景 | 对本项目 |
|---|---|---|---|
| Qt Quick 3D | PySide6 自带，但要写 QML，Python↔QML 传数据要绕一层；需要 GPU/RHI 后端 | 带材质、光照的产品级 3D 界面 | 只画线和坐标系，成本偏高；远程桌面 / 虚拟机上 RHI 不稳定 |
| VTK | `pip install vtk` 约 100 MB，打包体积大 | 科学可视化、点云、网格 | 功能远超需求，部署最重 |
| pyqtgraph.opengl | 需要 PyOpenGL；依赖显卡驱动 | 中等规模 3D 曲线 / 散点 | 可行，但无 GPU 环境、offscreen 测试会失败；中文标签麻烦 |
| MuJoCo 自带 viewer | 需要 mujoco；独立窗口 | 看仿真模型 | 不能嵌进 Qt 窗口，不能显示实机数据 |
| **QPainter 自绘透视投影（选用）** | **零额外依赖** | 几十条线段的线框 | 任何环境都能跑（含远程桌面、无显卡），offscreen 可截图测试，中文直接画 |

当前场景只有几十条线段（连杆、坐标轴、网格），QPainter 每帧 < 5 ms。以后要显示 STL 网格时再换成 Qt Quick 3D / OpenGL：渲染器只依赖 `DHTable + q_deg`，替换只动 `view3d.py`。

## 2. 坐标与单位

* **DH 约定**：改进 DH（Craig），与固件 `dh.c` 完全相同：`T_i = RotX(α)·TransX(a)·RotZ(q_i+θ偏置)·TransZ(d)`，第 i 行对应关节 Ji。
* **两套坐标**：世界系 `O_w` 与 `Simulation/mujoco/BigArm/robot.xml` 一致；DH 基座 `O₀` 是 BigArm 的腰部连杆坐标系，对应 `main.cpp` 里 `joint1` 之后的 link1。`joint2..joint8` 对应 DH 的 7 行 J0..J6。
* **腰部安装**：世界系到 DH 基座的变换取自 `main.cpp` 的 `c.waist_mount = TransformFromXyzRpy(...)`，当前为 `xyz = (0.000558840342, -0.0208529944, 0.038) m`、`rpy = (90°, -90°, 0°)`。
* **帧编号**：帧 0 = DH 基座 `O₀`；关节 Ji 位于帧 i+1 的原点、绕帧 i+1 的 z 轴旋转。勾选“世界坐标（含腰部安装）”时，渲染器把全部帧和点云左乘 `base_transform` 转到世界系；取消后直接显示 DH 基座系，便于与 IK 目标对照。
* **单位**：DH 表与协议都用 deg / m，只在算三角函数时转 rad。
* **零位与方向**：用协议里的 `angle_deg`，即固件 `observer.joint_deg`——已减零点、已乘 `direction`。**固件已改为多圈角**，三角函数天然处理，不需要折叠。
* **末端姿态**：`euler_zyx_deg` 逐行照抄固件 `Matrix_ToEuler`，(roll, pitch, yaw) 与固件 `observer.euler_deg` 同口径。
* **测试**：`tests/test_kinematics.py` 从 `Simulation/ArmSim/main.cpp` 解析当前 BigArm DH 与腰部安装，并核对 q=0 的世界系各帧位置；旧固件 `module_init.c` 的参数仍由 `DHTable()` / `default_dh()` 单独保留，用于固件对照和重力拟合。

## 3. DH 参数表

启动时按顺序取：

1. `config/dh.json`（在"DH 参数"页点过"保存为默认"）；
2. `Simulation/ArmSim/main.cpp` 的 `MakeArmConfig()`：当前 BigArm 的 7 行 DH + `waist_mount` 腰部安装（**只读**，不修改源码）；
3. 内置 BigArm 副本（只拷了 Host 目录、读不到 ArmSim 源码时）。

"DH 参数"页可以直接改表（默认改完立即生效），也可以“恢复当前模型”（重新解析 ArmSim 的 DH + 腰部安装）、导入/导出 JSON，或“从设备读取”（PARAM_READ 0x0400，需要固件实现参数读写；模拟设备已实现）。设备协议只返回 7 行 DH，不包含腰部安装，因此读取设备 DH 时 Host 会保留当前 `base.xyz_m / base.rpy_deg`。

## 4. 操作

| 操作 | 效果 |
|---|---|
| 左键拖动 | 旋转视角 |
| 右键 / 中键拖动 | 平移 |
| 滚轮 | 缩放 |
| 双击 | 复位视角 |
| 单击关节球 | 选中该关节，左上角显示它的角度、目标、角速度、力矩、状态 |
| 等轴 / 前视 / 侧视 / 俯视 | 预设视角 |

显示开关：连杆、关节坐标系（总开关 + 基座/J0~J6 逐个开关）、关节转轴、关节名称、地面网格、世界坐标轴、世界坐标（含腰部安装）、坐标轴长度。

## 5. 数据源解耦

面板只接收一个"取最新样本"的函数，不知道数据来自串口、模拟设备、仿真还是回放：

* **实时数据**：当前连接的数据源；
* **手动滑块**：离线核对 DH 表；"取当前实时姿态"把实机姿态复制到滑块上。

## 6. 渲染频率

面板定时器 30 Hz（`config/settings.toml` 的 `ui.view3d_fps`）拉一次关节角；角度、视角、开关都没变时**不重绘**。三维面板不可见（切到波形页）时完全不计算。渲染只在 GUI 线程，不影响串口线程和波形刷新。

## 7. 工作空间可视化

“三维姿态”页右侧的 **工作空间** 标签用于显示**末端位置可达集**。六维位姿空间不能直接画成一个三维点云，所以这里固定末端姿态自由度不参与显示，只采样末端 `(x, y, z)`；同一个位置可能有多种姿态，点云越密只代表采样命中的构型越多。

操作步骤：

1. 切到 **三维姿态 → 工作空间**；
2. 选择关节限位：可点“读取设备限位”，也可以直接编辑每个关节的最小/最大单圈绝对角；
3. 选择 **IK 分支**：`全部 8 个分支` 汇总显示，或选 `分支 #0..#7` 只看该分支可达的末端位置；
4. 设置构型数和体素尺寸，点“计算并显示”；
5. 用 **前视 / 侧视 / 俯视** 看三个投影包络；转动视角可看三维形状；黄色十字是当前末端位置。

采样与显示：

* 关节限位内用固定种子的均匀随机采样（默认 10 万构型），七轴不用规则网格，避免维度爆炸；
* 分支编号与固件一致：bit0/bit1/bit2 分别对应 shoulder(λ2)、elbow(λ4)、wrist(λ6)，置位表示负号；选单个分支时按 `sinθ2 / sinθ4 / sinθ6` 的符号过滤构型，再做正运动学，而不是给汇总点云临时染色；
* 用 `armhost/kinematics/workspace.py` 的批量正运动学求末端位置，再按体素合并；默认最多保留约 1.8 万个点，保证 QPainter 拖拽仍然流畅；
* 点云颜色从深蓝到黄色表示体素占用密度（对数归一化），不是可达姿态的数量；
* 修改 DH、限位、分支、构型数或体素尺寸后会清除旧点云，要求重新计算，避免把过期结果显示成当前模型；
* 工作空间点在 DH 基座系计算；勾选“世界坐标（含腰部安装）”后，点云、当前末端十字和三维帧会一起转到 MuJoCo 世界系显示；
* 点云是静态结果，计算一次即可，不会随关节角或界面刷新重复采样。
