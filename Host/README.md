# 1
你是一名资深机器人软件架构工程师。我要开发一个跨 Windows 和 Linux 的 Python 机械臂上位机。使用 PySide6 构建桌面 GUI，使用 pyqtgraph 绘制实时波形，使用 PySerial 与真实机械臂串口通信，后续通过 Python API 或进程间通信接入 MuJoCo。需要获取每个关节的角度、角速度和实际输出力矩，并支持后续双向交互。

请先设计整体软件架构，不要立即生成完整代码。要求：
1. 划分 UI、通信抽象层、串口驱动层、协议编解码层、机器人状态模型、波形模块、三维显示模块、MuJoCo 适配器。
2. 设计真实硬件和仿真器可切换的后端接口。
3. 设计线程模型，避免串口读取、仿真计算和 GUI 相互阻塞。
4. 设计统一的关节状态数据结构，明确角度、角速度、力矩的单位和时间戳。
5. 说明模块依赖关系、目录结构、线程间通信方式、异常处理与日志策略。
6. 兼顾后续加入轨迹控制、参数调节、数据回放和仿真同步。
7. 给出分阶段实施计划和每阶段验收标准。
请明确区分已经确定的需求与需要我补充的信息，不要擅自假定机械臂自由度、控制模式或硬件协议。
# 2
你是一名熟悉嵌入式 C、UART 和机器人控制系统的通信协议工程师。请为 Python 上位机与 STM32 机械臂控制器设计一套可靠的串口通信协议。

需求：
- 上位机读取所有关节的角度、角速度、实际输出力矩以及可用的状态和故障信息，具体可以参考Real\DIYcontroller的stm32工程实现。
- 支持设置关节输出力矩以及关节序号，但是只做设置，实际的力矩can通信发送由单片机的遥控器发送。
- 考虑帧头、协议版本、消息类型、序号、数据长度、负载、CRC 校验。
- 明确字节序、整数和浮点数编码、单位、正方向、角度采用 deg、力矩采用 N·m、时间戳定义。
- 定义状态上报、控制命令、参数读写、心跳、错误报告等消息类型。
- 设计粘包、拆包、丢字节、错误帧、超时、序号回绕和 CRC 失败处理。
- 给出具体帧格式、每个字段的字节偏移、示例十六进制帧及其逐字节解释。
- 分别给出 STM32 HAL C 端打包/解包示例，以及 Python 端编码器、解码器和单元测试。
- 设计版本兼容机制、最大帧长度和通信速率建议。

不要假定关节数量、波特率、上报频率或现有 MCU 协议。请将这些作为待确认参数，并说明建议值及其依据。考虑控制命令的超时保护、限幅和急停机制；串口断开后不得无限期保持未经确认的运动命令。
# 3

1. 提供可复用的 SerialTransport 类，支持端口枚举、连接、断开、参数配置和异常恢复。
2. 使用独立工作线程读取串口，不能在 GUI 主线程执行阻塞式读取。
3. 将接收字节流交给独立的帧解析器，支持不完整帧、连续多帧、错误帧和重新同步。
4. 将解码后的消息转换为和实际的单片机工程类似的结构体显示，需要和单片机侧同步。
5. 支持发送队列、写入错误处理、命令序号和应答匹配。
6. 提供日志记录、原始十六进制数据查看、接收统计、丢帧和校验错误统计。
7. 提供可注入的虚拟串口或模拟数据源，使没有连接真实机械臂时也能测试。
8. 给出完整文件结构、类型定义、单元测试和运行示例。

严格使用已确认的协议字段，不要自行发明数据偏移或命令编号。

请为我的 PySide6 机械臂上位机开发监视界面，使用 pyqtgraph 显示实时数据。数据通过独立通信模块提供的信号或线程安全数据接口获得。
